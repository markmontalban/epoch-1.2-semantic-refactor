**Scope note.** This note describes the local-only fine-tuning and content lane
that lives in `Projects/mt-private`. That project holds proprietary customer
content under a hard local-only policy, so **nothing here quotes message bodies,
module titles, or customer data** — only architecture, counts, and infrastructure
state. The corpus itself never leaves that folder.

---

## 1. What this lane is

A local-only environment for two goals:

1. **A safe agentic space for drafting mindfulness notifications** that fit the
   learning systems at `dev.mindfultext.com` — generated by local models,
   screened automatically, approved by Mark before anything reaches production.
2. **A fine-tuned model that writes in the MindfulText voice**, trained on the
   existing message corpus and served locally.

**Why local.** The corpus is customer-facing mindfulness content that was never
consented for third-party processing. Policy is absolute: content is generated,
trained, and served on one Mac Studio, with inference through Model Ops at
`http://localhost:7070/v1`. No cloud providers, no Colab, no Hub uploads.

**Product thesis this serves.** Mobile apps lose roughly 90% of users; messaging
retains them. Messaging plus microlearning drives long-term retention and real
habit adoption, and mindfulness is the skill domain. The channel is two-way —
messages carry reply calls to action — which is the structural advantage over app
push notifications, and it is why message *type* is a product concern rather than
mere data hygiene.

## 3. Capabilities available today

- **Local inference across seven models**, including a 27B dense, a 35B MoE, a
  35B agentic model, and a 33B coder. Sufficient for drafting, classification,
  and code generation without any external call.
- **Embeddings** via `bge-m3:latest`, for retrieval over the corpus rather than
  memorizing it.
- **A converted corpus**: every message parsed out of the production export into
  one JSONL row each, with heuristic type labels, CTA detection, and anomaly
  tracking.
- **A human labeling surface**: a CSV with one row per message and empty columns
  for type and training-eligibility.
- **A documented fine-tune path** end to end — dataset build, LoRA training,
  evaluation on held-out modules, GGUF export, Ollama registration.

## 4. Capabilities NOT yet available

- **No training stack installed.** No `mlx`, `mlx-lm`, `unsloth`, or `torch`; no
  virtual environment; no Unsloth CLI.
- **No trained model.** No adapters, no fused weights, no GGUF, no new Ollama id.
- **No generation space.** The draft → automated check → review queue loop is
  designed but not built.
- **No content registry or naming system.** Drafted, not implemented.
- **No write path back to production.** Content drafted locally has no
  reviewed route into `dev.mindfultext.com` yet.

### 5.1 The corpus, and the discrepancy that was resolved

The live API holds **283 modules and 1,112 texts** for the org. An earlier
estimate of "71 modules, ~355 messages" caused a long false alarm about the
converter over-splitting by 4×. It was not over-splitting. The estimate described
a **curated 71-module subset** that is an exact subset of the full export — all
71 of its headings appear verbatim in the full one, none unique to it.

That subset turns out to be useful: membership in it is a **hand-made curation
signal**, so 71 sections can be marked as vetted without any labeling effort.

The converter's remaining gap against live truth was **two messages**, caused by
an invented `__` delimiter that occurs exactly twice in the source. Removing it
should reconcile the count exactly.

### 5.2 The immediate blocker

**The converter was fixed but never re-run.** The script was edited on 2026-07-30
at 15:59; its outputs are from 2026-07-29 at 23:47 — sixteen hours *older* than
the code that should have produced them. The fixes are present in the file
(argument parsing, the `__` rule removed, curation flag, boundary assertions),
but nothing has exercised them.

Everything downstream — labeling, dataset build, training — is waiting on a
command that takes seconds. And because **zero rows are labeled**, this is the
cheapest possible moment to re-run: message ids can change at no cost. After
labeling begins, an id change orphans the work.

### 5.3 The known hard blocker

**Python 3.12 is not installed** and the system Python is 3.14, which is ahead of
the ML wheels the trainer needs. This requires a system-level install and is the
one item that cannot be done by an agent.

## 6. Design decisions already settled

- **Trainer: Unsloth Studio**, which has official Mac training support and writes
  the GGUF and `Modelfile` with the chat template used at training time —
  the usual cause of a fine-tune that looks fine in training and loops at serve
  time. `mlx-lm` is the scriptable fallback. Unsloth's Core Python package does
  not yet support Apple Silicon and would require cloud NVIDIA, which the policy
  gates.
- **Base model: `Qwen/Qwen3.6-27B`** — official bf16 safetensors, ~54 GB. The
  local Ollama copy is a 4-bit GGUF and cannot be fine-tuned; the two are
  different artifacts of the same model.
- **Taxonomy precedes training.** A model trained on unlabeled messages learns
  the average of an intro, a quote, a science note, and a quiz. Labels are what
  make it useful, so labeling gates the fine-tune rather than following it.
- **Identity is the upstream 8-character string id** (`"00000023"`). Names are
  free text and safe to change. The real fragility is that texts are addressed
  *positionally* within a module, so inserting or reordering silently remaps
  references — appending is safe, insertion is not.
- **Two content risks are treated as safety issues, not quality issues.** A model
  trained on quotes without knowing they are quotes learns to fabricate
  attributions; trained on science notes, it learns to invent studies. Both are
  liabilities in a mindfulness product, so both are gated by type labels and by
  automated checks before human review.

## 7. Critical path

1. **Re-run the converter** and confirm ~283 sections, 1,112–1,113 messages, 71
   curation matches, and clean boundary assertions.
2. **Install Python 3.12 and build the training venv.** Independent of labeling,
   so it runs in parallel — and it holds the only unknown-duration blocker.
3. **Label the corpus.** The long pole, and the gate on everything after it.
4. **Build the ChatML dataset** from eligible, labeled rows, holding out whole
   modules for eval.
5. **Train, evaluate on held-out modules, export, register in Ollama**, and
   confirm the new id appears on `:7070`.

Steps 1 and 2 are unblocked right now. Step 3 is Mark's time. Steps 4 and 5 are
documented in full.

## 9. Boundaries

- **Content never leaves `mt-private`** — no cloud model, issue tracker, chat,
  web search, or hosted notebook. Inbound downloads of public model weights are
  fine; outbound content is not.
- **The local agent never connects to the production API.** The Replit layer
  holds that access; the handoff between them is a file copied onto the machine.
  Credentials stay out of the local lane.
- **Inference stays on `:7070`** with literal model ids from `/v1/models`.
- **Nothing reaches production without Mark's approval**, and no push, PR, or
  outbound action happens without it either.
