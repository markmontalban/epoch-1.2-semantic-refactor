## Purpose and test boundary

This is the independent acceptance and abuse-case matrix for the private
Growth Ops foundation. Execute destructive or failure-injection cases only in
an isolated Neon development/test environment and a Vercel preview or local
environment. Do not place credentials, real growth records, production URLs,
or secret values in test fixtures or evidence.

**Severity meanings:** Critical = could expose data or mutate production;
High = could bypass a security/reliability boundary; Medium = degrades an
operational control or investigation; Low = does not presently affect a
security boundary.

## Execution rules

- Run all automated rows in CI against disposable, synthetic fixtures. A test is
  incomplete if it only observes an HTTP status and does not prove the required
  lack of durable side effects.
- Run manual drills before W2 acceptance and after material changes to auth,
  migration tooling, deployment controls, or recovery runbooks. Preserve only
  redacted evidence and record the environment, commit, tester, date, and
  request IDs.
- Treat any Critical failure as a W2 release blocker. Treat a High failure as a
  blocker unless a dated, explicitly approved exception defines scope, owner,
  and expiry.
