## DR-22 — Prototype run-first workflow

Epoch 1 now operates as a lightweight learning loop:

```text
5-minute founder brief → draft 3–5 opportunity paths → Mark edits/ranks → choose one next test
```

The founder brief is the minimum input for Run 001: product, intended buyer,
pain, current proof, and tentative offer. It must be safe to provide to the
manually selected agent. The original four evidence assets remain useful
enrichment, but physical import of all four is no longer a prerequisite for
draft paths. Any path based only on the brief is explicitly labeled a
`founder-assumption`, not validated evidence.

Hermes may perform manually prompted prototype work without C4. Telegram is
not part of the prototype workflow: no Telegram configuration, consumer
identification, or inbound task creation is required. The prior C4 checks are
deferred until a real Telegram or autonomous-Hermes integration is proposed.

The 24-hour local-model stability observation becomes background telemetry,
not a Run 001 or Run 002 gate. A local-first comparison may run with its
ordinary pre-run snapshot; any core eviction, 503, or other instability simply
makes that comparison inconclusive and informs the next optimization.
